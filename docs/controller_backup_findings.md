2. `RAPID/TASK1/PROGMOD/Modul1.modx` 保存的当前状态是
   `PERS num toolState := 2`。
3. `RAPID/TASK1/PROGMOD/Get_tool.modx` 中 `Get_toolP()` 完成后写入
   `toolState := 2`；`ToolJudge()` 也把任务 2 映射到 `Get_toolP()`。

据此，本项目把“备份时正在使用的 P 工具”作为第一阶段验证工具。桥接模块直接
引用全局 `tool_P`，并在接受运动前检查 `toolState = 2`，避免维护第二份可能失配的
工具数据。

## 相机、吸取动作和既有运动

- 相机准备点 `Redy_Camara_Palletizing` 的平移坐标为
  `[387.63, -161.81, 218.35]` mm，现有指令使用 `MoveL`、`tool_P` 和 `wobj0`。
- 码垛流程先移动到 `P_pick`，然后 `Set IIO_do2`；放置完成后
  `ReSet IIO_do2`。从调用位置判断，`IIO_do2` 很可能是 P 工具的吸取输出，但
  I/O 配置只有通用名称，备份本身不能证明它具体接的是哪只阀。
- `IIO_do5` 在进入相机准备/识别流程前置位，在流程节点间复位或再次置位。它的
  物理用途同样没有被 I/O 名称明确标注，不能仅凭代码断定。
- 现有相机 Socket 地址是 `192.168.0.220:777`，PLC Socket 地址是
  `192.168.0.100:4999`，两者均由 RAPID 作为 TCP 客户端连接。这也证明当前程序
  已经实际采用 RobotWare Socket Messaging。
- 本项目的新接口是控制器管理网口 `192.168.125.1:55000` 上的 TCP 服务端，
  不复用或修改上述相机、PLC 端口。

## 未直接复用既有运动点的原因

备份还包含 `P_pick`、`P_put`、`P_overassput1`、`Psafe`、`Phome` 以及多个相机
准备点。这些点属于原生产流程，部分依赖 `wobjPalletiz`、偏移量、夹具和现场布局。
仅从备份无法重新确认其当前路径是否无碰撞。因此第一版不会让 Python 调用这些点，
仍按计划在现场捕获新的关节目标 `pyHome` 和 `pyTest`。

## 必须现场复核的两项

- 目视确认当前机械端确实是 P 工具，并确认相机、吸盘及线缆在两点间无干涉。
- `tool_P` 的质量在备份中仅为 `0.001 kg`。本项目为保持与现有程序一致而直接
  复用，但这看起来不像吸盘和相机总成的真实质量。首次低速验证不要擅自修改；后续
  应由设备负责人依据实物重新核定工具负载和重心。

备份未被修改。
